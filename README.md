# StepFun Cookbook

围绕阶跃星辰（StepFun）模型的使用，整理实用案例、示例代码和辅助脚本，帮助开发者从具体问题出发，理解实现思路、运行示例，并将方法应用到自己的项目中。

本仓库目前用于集中存储和整理 Cookbook 内容，后续逐步补充案例。每篇案例以一个明确的任务为起点，尽量提供完整的操作步骤、必要的示例数据和结果说明，方便查找、复现与复用。

## 你可以在这里找到什么

计划整理以下几类内容，具体以已收录案例为准：

- **入门示例**：环境准备、API 调用和基础交互，帮助完成第一次运行。
- **场景实践**：围绕文档处理、信息提取、内容生成等任务，展示从输入到输出的完整过程。
- **实现技巧**：提示词组织、上下文处理、结果解析等可复用的方法。
- **工具脚本**：环境配置、数据预处理、格式转换等可独立运行的辅助工具。

内容可以采用 Jupyter Notebook、代码文件或 Markdown 教程的形式，按案例需要组织。

## 目录结构

仓库按以下结构存放内容。尚未加入内容的目录使用 `.gitkeep` 占位，加入实际文件后可移除。

```text
StepFun-Cookbook/
├── README.md            # 仓库介绍与内容导航
├── examples/            # Cookbook 案例，每个案例一个子目录
├── scripts/             # 可独立使用的工具脚本
│   └── claude-key-setup/ # 为 Claude Code 配置 StepFun 的工具
├── assets/              # 多个案例共用的图片、截图、流程图等素材
└── data/                # 多个案例共用的示例数据
```

**案例相关文件尽量放在一起。** 一篇案例专用的代码、图片和数据随案例存放；只有多个案例共用的资源才放到根目录的 `assets/` 或 `data/` 中，方便单独下载、移动和维护案例。

例如，一篇文档信息提取案例可以按下面的方式组织：

```text
examples/
└── document-extraction/
    ├── README.md        # 任务介绍、运行步骤与结果说明
    ├── example.ipynb    # 案例实现，也可以使用 .py 等代码文件
    ├── requirements.txt # Python 案例所需依赖，按需提供
    ├── data/            # 该案例使用的示例文档
    └── assets/          # 该案例的插图与结果截图
```

上面是组织方式示例，并非已收录案例。

## 如何使用

1. **选择案例**：根据要解决的问题，找到对应案例，先阅读其 README 或 Notebook 开头的说明。
2. **准备环境**：按照案例要求安装依赖，准备示例数据；需要调用 API 时，配置相应的 API Key 和模型参数。
3. **运行示例**：按顺序执行 Notebook 单元格，或按说明运行代码和脚本。
4. **查看与调整**：对照结果说明检查输出，再替换为自己的输入，调整提示词或参数。

不同案例可能使用不同的运行环境和依赖，请以各案例说明为准。API Key 通过环境变量或案例说明中指定的本地配置方式提供，真实密钥不应写入提交到仓库的代码或 Notebook。

## 工具脚本

`scripts/` 用于存放可独立使用的工具，例如环境配置脚本、数据转换工具和批量处理脚本。仅服务于某篇案例的代码应保留在该案例目录中。

- 单文件工具直接放在 `scripts/` 下，文件名说明用途。
- 包含多个文件或不同操作系统版本的工具，使用独立子目录。
- 每个工具说明用途、依赖、运行命令、输入和输出；涉及文件修改时，说明修改范围。

具体工具的使用方法见各工具目录中的说明文档。

## 内容整理约定

为了让案例便于理解和复现，新增内容时建议包含：

| 内容 | 需要说明的问题 |
| --- | --- |
| 任务目标 | 解决什么问题，适合什么场景？ |
| 运行准备 | 需要什么环境、依赖、模型和输入数据？ |
| 实现步骤 | 如何运行，关键步骤为什么这样设计？ |
| 结果示例 | 预期输出是什么，如何判断是否完成任务？ |
| 适用范围 | 有哪些限制、常见问题和可调整参数？ |

示例数据优先使用公开、脱敏或模拟数据，并标明来源或性质。Notebook 提交前检查输出单元格，避免保留密钥、个人信息或不必要的大段运行日志。引用外部代码、数据或素材时，保留来源及相应许可说明。
